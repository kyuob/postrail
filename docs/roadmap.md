# Postrail v0.1.0 개발 계획

목표: Markdown 하나를 네 플랫폼으로 보내고 결과를 추적하는CLI. 오프라인CLI, 개별 어댑터와 [공통 publish](publish.md)를 제공한다. KeyFlow추가 검증은 종료했다. Velog/Tistory/Blogger의 초안·비공개와 지정 원고의 공개 발행·같은ID 수정·데스크톱 이미지 클릭을 확인했다. [7단계](stage7-status.md)의 문서·로컬 설치·원격CI9개job을 검수했으며, 첫 배포 범위는 [v0.1.0 GitHub릴리스](release-0.1.0.md)다. npm은 `@kyuob/postrail`로 준비하고 별도 공개 전까지 `private:true`를 유지한다.

KeyFlow는 사용자 확정으로 추가 검증에서 제외한다. Velog/Tistory/Blogger의 실계정 검증은 승인 범위로 [묶어서 진행](bundled-validation.md)했고,[후속공개원고](publication-fable52.md)로화면과클릭을확인했다. 지정원고·환경의증거를 네플랫폼 모든기능의검증으로확대하지않는다.

## 2. 공통 원고와 오프라인 명령

- Bun 개발·빌드, Node.js 22+ 배포 실행을 유지한다.
- `postrail init`: 프로젝트 설정 예제 생성. 기존 파일은 기본적으로 덮어쓰지 않는다.
- `postrail validate article.md`: 필수 제목·안정적인 원고 ID, 태그, 공개 상태, 대상 플랫폼, 이미지 경로를 검증한다.
- `postrail preview article.md`: 네트워크 요청 없이 원고를 렌더링한다. 원고의 실행 가능한 HTML을 기본 비활성화한다.
- `postrail plan article.md --to velog,tistory,keyflow,blogger`: 전송 대상·상태·지원하지 않는 기능을 표시한다. 원격 쓰기와 인증 정보 접근은 하지 않는다.
- 기계용 `--json`과 사람이 읽는 출력을 구분한다. 실패 시 0이 아닌 종료 코드와 안정적인 오류 코드를 반환한다.
- 일반 설정·원고·발행 이력과 로그인 세션을 분리한다. 원고 ID는 파일 이동 후에도 유지하며, 본문 해시는 변경 감지 용도로 사용한다.

완료 증거: 한국어 제목, 코드블록, 표, 링크, 로컬 이미지 예제의 결과 확인. 잘못된 메타데이터·없는 이미지·기존 설정 충돌에 대한 검증. plan/preview가 쓰기 전송 함수를 호출하지 않는 검사.

## 플랫폼 어댑터

공통 계약은 `capabilities`, `authStatus`, `create`, `get`, `update`, `uploadImage`를 기준으로 설계한다. 초안·비공개·공개를 구분하며 플랫폼이 지원하지 않는 상태를 다른 상태로 몰래 변환하지 않는다. 공개 상태를 명시하지 않은 원고는 공개 전송하지 않고, 지원 가능한 초안/비공개 방식을 확인하도록 안내한다.

KeyFlow 공식 CLI 계약과 기존 검증 기록은 유지하되, 사용자 결정으로 추가 검증을 진행하지 않는다. subprocess 인자는 배열로 전달하며 셸 명령 문자열로 원고 내용을 조립하지 않는다. Blogger는 공식 API v3의 초안/발행 상태와 OAuth를 사용하며, 개별 비공개 게시글이나 로컬 이미지 업로드를 근거 없이 약속하지 않는다.

Velog는 공식 v3 소스와 읽기 전용 스키마 조회를 바탕으로 구현했으며 초안 실검증을 통과했다. Tistory는 종료된 Open API 대신 내부 관리 인터페이스를 사용하며 비공개 실검증을 통과했다. 둘 다 일반 Chrome의 전용 프로필에서 사용자가 로그인하고 완전히 종료한 뒤 계정을 확인한다. 기존 브라우저의 쿠키 DB를 읽거나 복호화하지 않는다. 세션은 사용자 소유 로컬 저장소에 제한된 권한으로 보관하고 로그·Git·JSON 출력에서 제외한다.

완료 증거: 승인된 테스트 원고의 생성 → ID 조회 → 이미지 확인 → 동일 ID 수정. 인증 만료·권한 오류·타임아웃을 구분한다. 공개 글 전송 검증은 해당 원고에 대한 사용자 승인 후 수행한다. 소스 검사나 모의 응답 성공만으로 live 지원을 표시하지 않는다.

## 6. 중복 방지와 복구

- 원고 ID + 계정 + 대상 블로그 + 플랫폼으로 발행 대상을 식별한다.
- 원격 ID·URL·공개 상태·확인된 원고 해시·마지막 작업 결과를 원자적으로 기록한다.
- 상태는 `pending`, `succeeded`, `failed`, `unknown`으로 구분한다. 제출 전 기록과 파일 잠금으로 같은 대상의 동시 생성을 막는다.
- 쓰기 직후 연결이 끊기면 `unknown`으로 기록한다. 원격에서 기존 결과를 확인하기 전 자동 재생성하지 않는다. 클라이언트 기록만으로 exactly-once를 보장한다고 주장하지 않는다.
- 여러 대상 중 일부만 성공하면 성공 결과를 유지하고 부분 실패를 출력한다. 확실한 실패 대상만 재시도한다.
- `status`와 `update`는 저장된 원격 ID를 사용한다. 원격 본문이 사용자가 직접 고친 상태라면 충돌을 알리고 덮어쓰기 전에 해결한다.

완료 증거: 4개 대상 중 일부 실패, 전송 직후 응답 유실, 로컬 기록 실패, 강제 종료, 동시 실행, 원고 이동, 원격 수동 수정 시나리오. 잘못된 블로그·계정의 ID를 재사용하지 않는지 검증한다. 공통 복구 테스트에 모의 응답을 사용하며 KeyFlow 전용 추가 실계정 검증은 재개하지 않는다.

## 7~8. 오픈소스 품질과 릴리스

- 한영 README, 실제 설치·사용 예제, 플랫폼별 지원표, 문제 해결, CONTRIBUTING, SECURITY, CHANGELOG를 제공한다.
- 예제에는 원고·테스트용 이미지·설정만 포함하며 계정·세션·발행 이력은 제외한다.
- Node.js 22/24 및 macOS/Linux/Windows의 오프라인 CLI CI를 구성한다. 브라우저 어댑터의 실제 지원 OS는 별도 증거로 표시한다.
- Bun으로 배포 패키지를 준비하고 깨끗한 디렉터리에 설치해 bin·의존성·필수 파일을 확인한다. 배포 이름 사용 가능 여부를 확인한 뒤 package.json의 private 설정 변경을 결정한다.
- 플랫폼 E2E는 승인된 계정·테스트 원고로 별도 실행한다. 외부 PR CI에 개인 인증을 제공하지 않는다.
- 기능 단위 커밋 예시: `feat(core): validate Markdown article metadata`, `feat(velog): add verified post publishing`, `fix(state): preserve uncertain publish outcomes`.

릴리스 게이트: 설치·오프라인 검사·나머지 플랫폼 실제 검증이 통과하고, 알려진 제약과 라이선스 고지가 문서에 반영되어야 한다. KeyFlow는 사용자 확정으로 수용하며 추가 검증을 차단 조건으로 삼지 않는다. Git 커밋/푸시와 별개로 패키지 발행·릴리스 공개·실제 블로그 게시는 각각 명시적 승인 범위를 확인한다.

1차 범위 밖: AI 원고 생성, 예약 발행, 통계, 댓글·좋아요·팔로우, Notion 가져오기, GUI, 글 삭제. 외부 API·브라우저 변경은 유지보수 항목이며 오픈소스의 영구적 완성을 약속하지 않는다.
