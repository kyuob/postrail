# 이미지 용량 확인

`postrail images article.md`는 로컬 이미지의 크기를 확인하는 오프라인 명령이다. 원본·원고를 변경하거나 로그인·이미지 다운로드를 하지 않는다. 용량을 초과한 원고도 목록을 출력한다.

```sh
postrail images ./article.md
postrail images ./article.md --json
```

파일별 바이트·참조 횟수·초과량과 전체 합계를 출력한다. 파일당 제한은 5MiB(5,242,880바이트), 합계 제한은 20MiB(20,971,520바이트)다. 제한과 같으면 통과하며 초과하면 종료 코드1, 정상 범위면0이다. 잘못된 원고·누락 파일·허용되지 않는 경로도 종료 코드1로 거절한다.

같은 이미지 경로가 반복되면 합계에 한 번만 센다. `a.png`와 `./a.png`처럼 Markdown에 기록된 서로 다른 경로는 기존 전송 방식에 맞춰 각각 센다. 실제 파일 경로를 기준으로 중복을 제외한 `uniqueFiles`, `uniqueFileBytes`도 보여 준다. 하드링크의 같은 물리 파일까지 합치지는 않는다. 외부 이미지는 표시만 하며 로컬 합계에 포함하지 않는다.

PNG/JPEG/GIF/WebP의 확장자와 기본 시그니처만 확인한다. 최대12바이트 헤더와 파일 크기를 읽으므로 큰 파일 전체를 메모리에 올리지 않는다. 완전한 이미지 디코딩이나 플랫폼 지원 검사는 아니다. Blogger의 로컬 이미지 미지원 등은 별도 플랫폼 검사에서 확인한다.

## 용량을 초과하면

1. 원본을 보존하고 원고 폴더 안에 `prepared-images/` 같은 별도 폴더를 만든다.
2. 필요한 해상도와 품질을 직접 확인하며 작은 사본을 준비한다. GIF/WebP 변환은 애니메이션·투명도·색상을 바꿀 수 있으므로 주의한다.
3. Markdown 이미지 경로를 사본으로 변경한다. 이 도구는 자동 변환하거나 무손실 최적화를 보장하지 않는다.
4. `images`, `validate`, 플랫폼별 `check` 또는 `publish --dry-run`을 다시 실행하고 미리보기에서 이미지를 확인한다.

실제 발행 전에는 [지원 범위](support.md)와 [오프라인 명령](offline-cli.md)을 함께 확인한다. `images`의 성공만으로 전송 가능 여부를 판단하지 않는다.
