# 묶음 실계정 검증 현황

2026-11-10 (Asia/Seoul). 사용자 지정 계정과 검토된 로컬 원고 3쌍으로 Blogger·Velog·Tistory의 생성·같은 ID 수정·조회·변경 없는 전송 건너뛰기와 원본 보존을 확인했다. KeyFlow 추가 검증은 하지 않았다. 계정·블로그·게시글 ID와 원고/이미지 해시, 실행 증거는 Git에서 제외한 `.postrail/validation-20261110/`에 둔다. 자격증명은 이 폴더나 공용 로그에 넣지 않는다.

## Google Blogger — API 범위 확인

| 항목 | 관찰 결과 |
| --- | --- |
| 실제 Desktop OAuth | 사용자 브라우저 동의 후 Blogger 사용자 ID 확인·별칭에 연결 |
| 관리자 블로그 | 사용자 지정 이름과 ADMIN 대상 확인 |
| 생성 | 준비한 원고로 초안 1개 생성, 원격 ID 보존 |
| 첫 조회 | 인증된 ADMIN 조회의 제목·HTML·태그·DRAFT 상태 일치 |
| 수정 | 검토된 한 문장만 추가, 같은 원격 ID 유지 |
| 두 번째 조회 | 수정 본문과 DRAFT 상태 일치 |
| 변경 없는 재전송 | 같은 ID로 skipped, 추가 글 없음 |
| 원본 보존 | 여섯 입력 원고·두 이미지의 SHA-256 유지 |
| 추가 확인 | 새 인증 조회도 마지막 저장 결과와 일치 |

공개 발행·삭제·기존 사용자 글 변경은 하지 않았다. 실제 원격 이미지/코드/표의 화면 표시, 토큰 만료 후 갱신, 서비스의 ETag/충돌 적용, public/revert는 미검증이다. 모의 검사의 통과를 이 기능들의 실제 성공으로 쓰지 않는다.

실제 `fetchUserInfo=true` 목록 응답은 `items` 없이 `blogUserInfos`에 결과를 반환했다. 이를 지원하고 ADMIN·블로그 ID 일치를 검사하도록 수정했다. null/잘못된 membership 회귀 검사를 추가했고 독립 읽기 전용 소스 검토에서 차단 문제는 없었다. 검토자는 계정·자격증명·실제 원격 결과에 접근하지 않았다.

## Velog — 실제 API 검증 통과

Velog는 사용자가 일반 Chrome 전용 프로필에서 Google 로그인을 완료하고 앱을 종료한 뒤, CLI의 정확한 계정 일치 확인에 성공했다. 준비한 테스트 초안 한 개 생성, 인증 조회, 같은 ID에 승인 문장 추가, 재조회, 변경 없는 전송의 skipped 처리 및 여섯 원고·두 이미지의 원본 SHA-256 보존을 실제 계정으로 확인했다. 글은 draft 상태로 유지했다. 이미지·코드·표의 실제 화면 표시는 아직 미검증이다.

Tistory 종료 후 전체 최종 조회에서 Velog의 기존 테스트 ID가 null이었다. 사용자가 검증 후 해당 초안을 직접 삭제했다고 명시 확인했다. 최초 생성·수정 성공 증거와 사용자 삭제 확인은 별도로 보존한다. 최종 Velog 검사는 원래 생명주기 증거와 정확한 계정으로 조회한 동일 ID의 부재를 함께 확인하며, 삭제를 현재 본문 조회 성공으로 바꾸어 기록하지 않는다. 새 초안 생성이나 덮어쓰기는 하지 않았다.

## Tistory — 실제 비공개 글 검증 통과

정상 Chrome 세션 복원 옵션 적용 후 수동 로그인과 백그라운드 블로그 호스트·숫자 ID 확인이 성공했다. 기본 재실행에서 세션 쿠키가 사라지는 현상은 별도 임시 프로필의 가짜 쿠키로 재현했고, 복원 옵션으로 보존되는 것을 확인했다. 인증 제한 우회나 기존 Chrome 쿠키 추출은 하지 않았다.

첫 비공개 생성은 글 ID를 반환했지만 편집기 조회 파서가 실패해 unknown 상태로 보존했다. 실제 설정의 `Config.post`, `category` 및 문자열 숫자 옵션을 지원하도록 수정했다. 저장 시 이미지 크기가 숫자에서 숫자 문자열로 바뀌는 차이는 크기·참조·스타일 변경을 계속 검출하는 범위에서 정규화했다. 빌드·smoke·112개 검사와 독립 소스 검토를 통과했다.

재생성 없이 이미 받은 글 ID를 읽고 원고·태그·이미지 표기·비공개 상태·편집기 옵션이 승인 내용과 일치하는지 확인한 뒤 로컬 unknown 상태를 복구했다. 같은 ID로 승인 문장만 추가했고, 재조회·변경 없는 전송의 skipped 처리·여섯 원고와 두 이미지의 SHA-256 보존을 확인했다. 비공개 상태를 유지했으며 원격 테스트 글은 삭제하지 않았다.

## 남은 검증

각 플랫폼의 인증 조회·저장 결과와 실제 화면/이미지 표시를 구분한다. 이미지·코드·표의 육안 확인, 만료 후 인증 갱신, 공개 발행·되돌리기, 광범위한 오류 복구는 아직 미검증이다. 수동 Chrome 로그인은 현재 macOS만 지원한다. 불확실한 write 결과는 보존하고 자동 재전송하지 않는다.
