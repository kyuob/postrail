# Postrail 전체 검수와 업데이트 계획

2026-11-10 · 검수 기준 커밋 `c03b98a` · 대상 버전 `0.1.0`

## 판정

최초 v0.1.0은 지정한 환경에서 실제 발행과 같은 글 수정을 확인한 **GitHub 사전 릴리스**다. 최초 검수에서 태그 검증과 발행 후 복구에 수정할 문제를 확인했다. 아래 재현·과거 증거는 당시 기록이며, 이후 구현은 다음 표와 [v0.1.2 릴리스 기록](release-0.1.2.md)으로 구분한다.

## 후속 구현 상태 · v0.1.2

| 이슈 | 로컬 반영 | 확인한 범위 |
| --- | --- | --- |
| R1 | 완료 | 두 어댑터 check/push의 태그 충돌 거절, 인증·쓰기0회, 공통 전송 사전 차단 |
| R3 | 완료 | 올바른 소유권·ID만 먼저 보존. 불완전 응답과 부분 GraphQL 오류는 unknown 유지, 다른 소유자·업데이트 ID 교체 거절 |
| R4 | 완료 | 공통 실패 결과의 로컬 상태·저장 ID·다음 확인 안내, 읽을 수 없는 이력의 안전한 처리, 임의 예외 데이터 제외 |
| R5·R6 | 완료 | 원고·대상 파일을 먼저 준비하는 설치 순서, 문서에서 추출한 빈 폴더 실행 검증, 한영 사전 릴리스·충돌 보호 범위 설명 |
| R2 | Velog 우선 구현 | 읽기 전용 진단, 이미지 바이트 검증, 검토 지문·명시적 태그 승인·잠금·백업을 갖춘 로컬 이력 대조. 다른 플랫폼은 미지원 |
| R7·R8 | v0.1.2 구현 | 오프라인 이미지 용량 진단, 원본 보존 안내, 격리 전역 설치·PATH·제거 및 릴리스 메타데이터·체크섬·허용 파일 검사 |

안정화 단계에서는 회귀193개(코어·세 어댑터168개와 공통 전송25개)가 통과했다. 문서에서 추출한 원고·대상·다섯 명령을 네트워크와 하위 프로세스를 차단한 빈 소비자 폴더에서 실행했다. 독립 코드 검토에서 지적한 `_`·`-`로 시작하는 유효 ID의 공통 출력 누락도 바로잡았다. 이 과거 증거를 실제 서비스 발행이나 개별 v0.1.1 릴리스 증거로 확대하지 않는다. 현재 패키지 버전은0.1.2다.

후속 R2에서는 Velog 복구 회귀를 더해 총225개를 검사한다. 소유권·원문·로컬 기록·원격 지문 변경, 정확한 두 공개 상태 플래그, 이미지 순서·바이트·호스트 제한, 잠금, 백업 생성·쓰기·동기화 실패, 정리 후 원격 충돌을 다룬다. 독립 검토에서 발견한 초안의 비공개 플래그 비교 누락도 수정했다. 검증은 합성 세션과 격리된 로컬 이력으로 수행하며 실제 서비스·CDN·사용자 이력의 복구를 검증했다고 확대하지 않는다.

검수 중 새 글 생성·기존 글 수정·로그인·자격증명 조회·원격 이슈 등록·푸시·릴리스는 수행하지 않았다. 기존 KeyFlow 수용 결정과 추가 검증 종료 상태를 유지했다. 외부 읽기는 GitHub 배포·CI와 공개 의존성 보안 권고 확인으로 제한했다.

## 이슈 목록

P1은 다음 배포에서 먼저 해결할 발행·복구 문제, P2는 그 뒤 해결할 신뢰성과 사용성 문제, P3는 검수 범위 확장이다. 보안 사고 등급을 뜻하지 않는다. 이번 범위에서 새 P0 결함은 확인하지 못했다.

### R1 · P1 · 대소문자 충돌 태그가 저장 후 실패한다 — 재현 확정

- 조건: 태그를 `[CLI, cli]`로 지정하고 Velog 또는 Tistory로 보낸다.
- 원인: [core.js](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/src/core.js)의 태그 중복 검사는 원문 문자열만 비교한다. [tags.js](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/src/tags.js)의 저장 후 비교는 ASCII 소문자로 접었을 때 중복이 있으면 항상 거절한다. 두 어댑터의 오프라인 검사는 이 조합을 미리 거절하지 않는다.
- 영향: 유효하다고 판정된 입력이 실제 쓰기 이후 `READBACK_FAILED`와 `unknown`으로 끝날 수 있다. 합성 Velog 사례에서 쓰기1회·원격 ID 보존·unknown 전환을 확인했다. Tistory도 같은 비교 함수를 사용한다.
- 수정: 영향을 받는 어댑터의 오프라인 검사와 직접 push 진입점에서 충돌 태그를 거절한다. 자동으로 태그를 삭제하거나 Unicode 전체를 임의 정규화하지 않는다.
- 완료 조건: 두 플랫폼 직접 명령에서 세션 접근·업로드·글 쓰기0회. 공통 전송은 마지막 대상에서 충돌을 발견해도 전체 쓰기0회. 정상 ASCII 대소문자 재사용과 원격 충돌 지문 검사는 유지한다.

### R2 · P1 · 발행은 됐지만 태그가 달라지면 일반 사용자가 복구하기 어렵다 — 실사용 확인

- 조건: 요청한 `QA`가 원격에서 `Q&A`로 저장된 사례. 본문·제목·이미지·소유자·공개 상태는 일치했다.
- 현 상태: [velog.js](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/src/velog.js)의 엄격한 비교는 불일치를 감지하고 중복 방지를 위해 unknown을 유지한다. 이 중단 자체는 필요한 보호다. 그러나 [FAQ](faq.md)에 명시된 대로 일반 복구 명령이 없어, 정상 발행 여부와 메타데이터 차이를 사용자가 구분하기 어렵다.
- 수정: 우선 읽기 전용 진단으로 저장 ID와 원격 상태, 본문/태그/공개 상태의 차이를 분리해 보여 준다. 다음 단계에서 검토한 원격 지문에 묶인 명시적 로컬 이력 대조 기능을 설계한다. 명령 이름과 옵션은 구현 설계 때 확정한다.
- 완료 조건: 정확한 계정·블로그·저장 ID·원격 최신 지문을 확인한다. 원격 글은 만들거나 수정하지 않으며, 차이를 표시하고 사용자 명시 확인 없이는 unknown을 성공으로 바꾸지 않는다. 소유자·본문·공개 상태 불일치와 오래된 확인 지문은 거절한다. 이전 이력 백업과 로컬 쓰기 잠금을 보장한다.
- 금지: 이 한 사례만으로 `QA`와 `Q&A`를 전역 동치 처리하거나, unknown을 지우고 재발행하지 않는다.

### R3 · P2 · 불완전한 Velog 저장 응답에서 반환된 ID를 놓친다 — 재현 확정

- 조건: 쓰기 응답에 올바른 소유자와 글 ID가 있지만 `body` 등 다른 필드가 빠진다.
- 원인: [velog.js](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/src/velog.js)는 전체 `validatePost`를 통과한 다음에야 ID를 기록한다. [velog-client.js](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/src/velog-client.js)의 GraphQL 처리도 오류와 함께 온 부분 데이터를 통째로 거절한다.
- 영향: 합성 응답에서 쓰기1회 후 unknown이 됐지만 글 ID가 이력에 남지 않았다. 자동 재생성은 차단되지만 서비스 관리 화면에서 수동으로 찾는 부담이 커진다.
- 수정: 소유권·ID를 확인하는 작은 검사와 전체 내용 검사를 분리한다. 신뢰할 수 있는 반환 식별자만 먼저 기록하고 이후 검증 실패는 계속 unknown으로 남긴다. 부분 GraphQL 오류도 성공이나 재시도로 취급하지 않는다.
- 완료 조건: 본문 누락·소유자 불일치·업데이트 시 ID 변경·부분 data와 errors 동시 응답을 검사한다. 올바른 ID만 보존하고 잘못된 소유자/ID는 기록하지 않는다. 이어지는 쓰기 재시도는 차단한다.

### R4 · P2 · 공통 전송 결과가 보존된 ID를 알려 주지 않는다 — 재현 확정

- 원인: [publish.js](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/src/publish.js)의 실패 결과에는 `error.code`와 `automaticRetry:false`만 있다. 실제 글 ID가 플랫폼 이력에 저장돼 있어도 공통 JSON에는 나오지 않는다.
- 영향: 출력의 `failed`만 보고 글이 전혀 생성되지 않았다고 오해하기 쉽다. 성공·실패·확인 불가를 구분하는 복구 안내가 부족하다.
- 수정: 버전 호환성을 유지하며 실제 로컬 상태, 검증된 저장 ID, 다음 읽기 전용 확인 동작을 구조화한다. 원격 API의 임의 오류 텍스트나 토큰·서명 URL은 출력하지 않는다.
- 완료 조건: ID가 있는 unknown/없는 unknown/명확한 전송 전 거절/성공·실패 혼합을 구분한다. 추가 원격 호출이나 재시도 없이 이력에서 확인된 정보만 반환한다. 사람이 보는 출력과 JSON을 함께 검사한다.

### R5 · P2 · 빈 작업 폴더에서 설치 가이드를 그대로 따라갈 수 없다 — 소스 대조 확정

- 위치: [설치 가이드의 프로젝트 준비 절](installation.md).
- 원인: `init` 다음에 바로 `validate ./article.md`와 대상 설정을 사용하는데, `init`은 `postrail.json`만 만든다. 예제 원고와 대상 파일을 준비하는 설명은 실행 블록 뒤에 있다.
- 수정: 예제 원고·대상 파일 준비를 명령보다 앞에 두고, 패키지 사용자와 소스 사용자의 실제 경로를 나눈다. 가짜 대상 설정의 dry-run과 실계정 전송도 구분한다.
- 완료 조건: 빈 소비자 폴더에서 문서의 순서만 따라 버전 확인→원고 준비→validate→preview→dry-run까지 실행한다. 인증·실제 글 쓰기 없이 재현 가능해야 한다.

### R6 · P2 · 요약 문서의 지원·배포 표현이 실제 범위보다 넓거나 오래됐다

- [English README](../README.md)의 공통 설명은 모든 어댑터가 원격 충돌을 막는 것처럼 읽힌다. 상세 문서는 KeyFlow의 원격 get/충돌 검출 부재를 분명히 밝힌다. Velog/Tistory의 사전 읽기 역시 읽기와 쓰기 사이의 동시 편집까지 원자적으로 막는 것은 아니다.
- 첫 릴리스의 `prepared` 표현과 실험적 버전 안내를 실제 **공개된 GitHub 사전 릴리스** 상태에 맞춰 한영 문서에서 일치시킨다. npm 미배포와 기능별 제약은 유지한다.
- 완료 조건: README·로드맵·지원표·릴리스 문서가 같은 상태를 설명하고, 오프라인 CI와 실제 로그인 검증을 구분한다. 과거 영문 발행 기록은 과거 증거로 유지하되 현재 게시 언어를 보장하는 문장으로 쓰지 않는다.

### R7 · P2 · 이미지 용량 초과의 원인과 해결 경로가 부족하다 — 사용성 개선

- [core.js](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/src/core.js)의 파일당5MiB·합계20MiB 제한은 [오프라인 가이드](offline-cli.md)에 명시된 동작이다. 제한 자체를 결함으로 분류하지 않는다.
- 실사용에서 설명 그림10장과 배너2장의 합계가 제한을 넘어 수동 준비가 필요했다. 현재 오류는 실제 합계·초과량·해당 이미지와 해결 방법을 충분히 안내하지 않는다.
- 수정: 오프라인 이미지 목록·파일별 바이트·합계·제한 초과를 진단하고, 원본을 덮어쓰지 않는 별도 준비 과정을 안내한다. 최적화 기능을 넣는다면 명시적 실행과 파생 폴더를 사용한다.
- 완료 조건: 원본 해시 보존, 임계값 경계, 중복 경로 집계, PNG/JPEG/GIF/WebP를 검사한다. 무손실 변환을 표방하면 픽셀·크기·색상 정보 및 애니메이션 보존을 검증하고, 보존 못 하는 형식은 거절한다. 단순히 제한을 높이지 않는다.

### R8 · P3 · 검수 자동화가 실제 배포 경로 전체를 덮지는 않는다

- [패키지 검사](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/scripts/package-smoke.mjs)는 별도 소비자의 로컬 의존성 설치를 검증한다. 설치 문서의 `bun add -g`와 전역 PATH·제거까지 같은 방식으로 검사하지는 않는다.
- [GitHub 확인 도구](https://github.com/kyuob/postrail/blob/c03b98a72b4388f79a28cc8df751e7f775e95922/scripts/verify-github.mjs)는 저장소·main·CI를 확인하지만 태그·사전 릴리스 상태·첨부 파일·체크섬까지 검증하지 않는다. 이번 검수에서는 해당 배포물을 별도로 내려받아 확인했다.
- 완료 조건: 격리된 전역 설치 위치에서 bin 발견·version/help·제거를 검증한다. 읽기 전용 릴리스 검사에 태그 커밋·성공 CI·배포 파일·체크섬을 포함한다. 기존 사용자 전역 설치나 셸 설정은 변경하지 않는다.

## 결함과 구분할 기존 제약

| 항목 | 처리 방향 |
| --- | --- |
| Blogger 로컬 이미지 업로드·개별 private 미지원 | 지원한다고 바꾸지 않는다. 우선 공개 이미지 URL 준비와 검증 절차를 개선하고, 호스팅 연동은 별도 범위로 설계 |
| Tistory draft 슬롯 미지원 | 기존 거절 유지. private/public으로 자동 변환하지 않음 |
| Velog/Tistory의 macOS Chrome 로그인 지원 | OS 확대는 별도 실환경 증거 확보 후 진행 |
| Blogger Windows 인증 저장 미지원 | ACL 검증 전 지원 선언 금지 |
| KeyFlow 원격 get·수동 수정 충돌 검사 부재 | 지원표 예외 유지. 사용자 결정대로 추가 전용 검증을 재개하지 않음 |
| 그림·예제와 본문 언어 불일치 | 발행 전 검토 항목과 언어별 원고 예제로 다룸. AI 자동 번역·이미지 재생성은 핵심 CLI의 기본 동작에 추가하지 않음 |
| 공개된 작성자 예시 글 링크 | 비밀 유출로 분류하지 않음. 특정 계정에 묶인 예제를 계속 사용할지 문서 유지보수 때 결정; 비공개 원고·이력·세션은 계속 배포 제외 |

## 실행할 업데이트 순서

| 순서 | 범위·이슈 | 산출물과 종료 기준 | 권장 커밋 단위 |
| --- | --- | --- | --- |
| 1 · v0.1.1 안정화 | R1 | 두 어댑터 오프라인 태그 검사와 공통 전송의 쓰기0회 회귀 | `fix(tags): reject ambiguous tag identities before publishing` |
| 2 · v0.1.1 복구 정보 보존 | R3·R4 | 소유권 검증된 ID 보존, 실패 시 저장 상태·다음 확인 단계, 부분 응답 회귀 | `fix(velog): retain verified identities from incomplete writes` / `fix(publish): report unresolved saved outcomes` |
| 3 · v0.1.1 배포 문서 | R5·R6 | 빈 폴더 설치 순서 실행, 한영 지원표와 사전 릴리스 상태 일치 | `docs: align onboarding and prerelease support claims` |
| 4 · v0.1.2 복구 도구 | R2 | 읽기 전용 차이 진단부터 구현한 뒤, 명시 확인·지문·잠금·백업을 갖춘 로컬 이력 대조 추가 | `feat(recovery): inspect and reconcile confirmed remote outcomes` |
| 5 · v0.1.2 이미지·배포 검수 | R7·R8 | 이미지 용량 진단, 별도 준비 가이드, 격리 전역 설치 및 읽기 전용 배포 검사 | `feat(images): explain local image budgets` / `test(release): verify global install and distribution assets` |
| 6 · 선택적 후속 기능 | Blogger 이미지 준비, 추가 OS, npm | 사용자 수요·지원 인터페이스·유지보수 비용을 보고 별도 확정 | 작은 기능별 변경으로 나눔 |

R1과 R3·R4는 따로 재현·수정·검증한다. R2는 그 정보 보존 위에 구현한다. 각 변경은 관련 회귀→문서→패키지 검사 순서로 확인하고, 어댑터 수정은 해당 명령의 검사 범위를 사용한다. 공통 모의 검사 때문에 KeyFlow 전용 검증을 다시 요구하지 않는다.

`@kyuob/postrail` npm 공개는 안정화와 설치 검수가 끝난 뒤의 별도 배포 선택이다. 소유권·인증·현재 패키지 버전과 `private` 전환·공개 파일 목록을 검토한 다음 새 승인으로 수행한다. GitHub 릴리스나 npm 공개를 이 계획 작성의 완료 조건으로 삼지 않는다.

## 다음 작업

R7·R8은 v0.1.2에 구현했다. `images`는 용량 초과 원고도 파일별·전체 바이트와 준비 방법을 안내하며 자동 변환하지 않는다. 패키지 검사는 전역 설치 위치를 명시적으로 격리하고 PATH·제거를 확인한다. 릴리스 검사는 태그 커밋의 최신 CI·첨부 파일·체크섬·패키지 허용 목록을 확인하고 선택적으로 검수한 로컬 패키지와 바이트를 대조한다. R2는 Velog부터 구현했으며 기존 실제 unknown 기록은 변경하지 않았다. npm 공개와 다른 플랫폼 복구는 별도 범위다. 실계정 검증과 자동 복구는 이번 작업에 포함하지 않는다.
