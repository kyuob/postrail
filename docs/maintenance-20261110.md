# CLI 유지보수 후속 작업

## 구현

- 여섯 명령 파서의 옵션 읽기 루프를 공통 함수로 모았다. 플랫폼별 허용 옵션, 위치 인자 허용 여부, 오류 문구와 명령 검증 순서는 유지한다.
- 플랫폼별 사람이 읽는 출력을 각 명령 모듈이 내보내는 출력 함수로 옮겼다. CLI 진입점은 명령 선택·JSON 출력·종료 상태를 담당한다.
- 공개 오류 코드와 종료 상태를 공통 계약으로 등록했다. 공통 publish는 등록된 플랫폼 코드만 전달하며, 등록되지 않은 접두사 문자열은 `PUBLISH_TARGET_FAILED`로 바꾼다. 문서 검사에서 핵심 코드·종료 상태·소스의 플랫폼 코드 등록 누락을 확인한다.
- Prettier3.9.10을 개발 의존성으로 고정했다. 소스·검증 스크립트·패키지 설정·CI 서식을 정리하고 `check:format`을 CI에 추가했다. 원고·사용자 문서는 포맷 대상에서 제외한다.

## 검증

- 빌드·스모크와 허용 범위 회귀264개 통과. KeyFlow 전용 검수는 추가 실행하지 않았다.
- 문서 예제·링크·오류 계약 검사 통과.
- 허용된 배포 파일29개, 별도 소비자 설치, 격리 전역 설치·PATH·삭제 통과. macOS arm64 / Node22.22.2이며 실제 사용자 설치를 변경하지 않았다.
- 고정 포맷터의 debug-check와 서식 검사 통과. 기능 수정 직후의 파일을 보존해 서식 변경과 구분했다.
- 별도 Codex 읽기 전용 리뷰에서 파서 정책·검증 순서·출력·오류 전달에 차단 결함 없음. Claude 검수나 실제 계정 검수로 표시하지 않는다.

## 외부 상태와 남은 입력

최초 검수 시점에는 로컬 소스 변경이었다. 이후 사용자 승인으로 원격 main에 푸시했고, 2026-11-11에 npm0.1.5로 공개했다. npm0.1.4 배포물은 변경하지 않았다. 정확한 후보 커밋·CI·registry 무결성·격리 설치 결과는 [0.1.5 배포 기록](release-0.1.5.md)을 따른다.

사용자가 단일 npm 명령의 예외를 명시적으로 허용하고 정상 브라우저 인증을 완료한 뒤 `0.0.0-stage`에만 사용 중단 경고를 추가했다. 당시 latest는0.1.4였다. 이번0.1.5 공개 후에도 stage 경고가 유지되고 최신 버전에는 경고가 없음을 확인했다. 버전 삭제나 패키지 전체 사용 중단은 하지 않았다. 나머지 작업의 Bun 전용 규칙은 유지한다.

기존 다른 세션의 [실계정 검증 기록](bundled-validation-results.md)에서 Velog의 전용 Chrome Google 로그인·계정 일치 확인과 Tistory의 수동 로그인·블로그 호스트·숫자ID 확인이 이미 통과했음을 재확인했다. 이후 [지정 원고 공개 검수](publication-fable52.md)에서도 인증된 재조회와 실제 화면 검증을 마쳤다. 일반 Chrome 로그인을 다시 미완료로 취급하거나 계정 입력·로그인을 재요청하지 않는다. 새 경로 지정 옵션을 사용하는 비표준 설치 위치의 실계정 검증은 별도 선택 검증이며, 기존 일반 로그인 증거가 그 옵션까지 검증한 것으로 확대하지 않는다.
