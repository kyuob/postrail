# 지원·검증 범위

구현, 모의 검사, 실제 계정 저장 검증, 실제 화면 확인은 다른 상태다. v0.1.0은 공개된 실험적 GitHub 사전 릴리스이며 npm 배포는 하지 않았다. 이 표는 모든 기능의 지원을 약속하지 않는다.

| 기능 | Velog | Tistory | KeyFlow | Blogger |
| --- | --- | --- | --- | --- |
| 연결 방식 | 전용 Chrome + 내부 v3 | 전용 Chrome + 내부 관리 API | 고정 버전 공식 CLI | 공식 API v3 + Desktop OAuth |
| draft | 지원 | 미지원 | 기존 계약 지원 | 지원 |
| private | 지원 | 지원 | 기존 계약 지원 | 미지원 |
| public | 지정 원고 실계정·화면 확인 | 지정 원고 실계정·화면 확인 | 기존 계약 | 지정 영문 원고 실계정·화면 확인 |
| 로컬 이미지 | 업로드·화면·클릭 확인 | 첨부 등록·화면·클릭 확인 | 기존 제약 참고 | 미지원, 검증된 공개CDN이미지 표시 확인 |
| 같은 원격 ID 수정 | 실계정 확인 | 실계정 확인 | 기존 사용자 확정 | 실계정 확인 |
| 변경 없는 재전송 | 원격 확인 후 skip | 원격 확인 후 skip | 로컬 해시로 skip | 원격 확인 후 skip |

KeyFlow의 자세한 이미지·상태 계약은 [기존 가이드](keyflow.md)를 따른다. 추가 검증을 다시 수행하지 않으며 새 검증 결과로 꾸미지 않는다.

충돌 검사는 저장 시점과 사전 조회 결과를 비교하는 보호다. 특히 Velog/Tistory의 조회와 쓰기 사이에 발생하는 동시 원격 편집까지 원자적으로 막지는 못한다. 로컬 잠금도 서비스 웹 편집기를 잠그지 않는다. 전송 중 같은 글의 다른 편집을 피한다.

## 실행 환경

| 범위 | macOS | Linux | Windows |
| --- | --- | --- | --- |
| 오프라인 CLI | 로컬·CI 통과 | CI 통과 | CI 통과 |
| Node.js | 22 이상, CI 22/24 | CI 22/24 | CI 22/24 |
| Velog/Tistory 수동 로그인 | 지원·실계정 확인 | 미지원 | 미지원 |
| Blogger 인증 저장 | 지원·실계정 확인 | 구현·실계정 미검증 | ACL 검증 전 미지원 |
| KeyFlow 인증 | 기존 공식 CLI 계약 | 공식 CLI 제약 확인 필요 | 공식 CLI 제약 확인 필요 |

Node22/24·세OS의 오프라인6조합과 Linux 패키지2조합이 실제CI에서 통과했다. 실행 기록은 [7단계 검수 기록](stage7-status.md)을 확인한다. 이 결과를 세OS의 실제 브라우저 로그인 성공으로 확대하지 않는다.

공통 `publish`는 선택한 대상의 공개 상태를 그대로 사용한다. 호환되지 않는 조합은 전송 전에 거절한다. [실계정 개별 검증](bundled-validation-results.md), 공통 다중 전송과 [실제 공개 글 검수](publication-fable52.md)를 구분한다. 공개 검수는 macOS Chrome의 지정 원고와 이미지12개·추천 이미지 클릭에 한정된다. 실기기 모바일, 만료 후 인증 갱신과 공개→초안 되돌리기의 실계정 검증은 별도 범위다.
