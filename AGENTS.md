# Postrail

Standalone open-source Markdown publishing CLI targeting Velog, Tistory, KeyFlow, and Google Blogger (target ID: blogger). Do not import code or configuration from sibling MyApp projects.

- Use Bun for dependencies and development commands. The built CLI runs on Node.js 22+.
- Run `bun run check` before proposing or committing a change.
- Offline init/validate/preview/plan, platform commands and common publish orchestration exist. KeyFlow acceptance is closed. Velog/Tistory/Blogger scoped draft/private create/read/same-ID update/skip validation passed; user removed the Velog test after verification. Common publish is mock-tested, not combined-live verified. Visual/public lifecycle checks remain unverified. Tistory draft slots and Blogger private/local images must never be converted silently.
- Common publish requires explicit destinations and confirmation, all-target offline preflight, sequential results, article and platform locks, and unchanged/unknown safeguards from each adapter. Do not add implicit login, retry, rollback, post recreation or privacy conversion. Generic mocks may test orchestration without reopening KeyFlow-specific checks.
- Do not initiate further KeyFlow-specific checks, live/proof tests or authentication unless the user explicitly reopens that work. Use bun run check:blogger for Blogger work, check:tistory for Tistory work, check:velog for Velog work and check:offline for target-only changes; keep existing automatic regression CI intact. This specific instruction takes precedence over the generic full-check instruction above.
- Blogger uses explicit Desktop OAuth client files, PKCE/state loopback, fixed Google endpoints, no automatic write retry, POSIX-private home credentials and user-ID binding. Never read another module's Google credentials. Require exact account/blog ID and ADMIN access; create draft before public publish, and revert/verify before sending new draft content to an existing LIVE post. Windows authentication is unsupported pending ACL validation. Keep live account work bundled; no public test writes without exact approval.
- Tistory internal API schemas are experimental. Require exact canonical blog and numeric blog ID, isolated Chrome profile, data-only Config parsing (no eval/VM), private/public distinction, POST create vs PUT ID-path update, registered image attachments, and pending/unknown protection. Never bypass login verification/CAPTCHA. Keep live account work deferred to the approved bundled validation stage.
- Velog must use the dedicated Postrail Chrome profile, never existing browser cookie databases or Keychain extraction. Require exact usernames, confirmation and owned post IDs. Preserve unresolved journals and never automatically retry writes or fall back to another mutation schema. Live login/post tests need an approved account and exact content.
- KeyFlow integration must use the pinned official CLI, preserve original articles, sanitize subprocess output, require explicit named accounts and upload confirmation, and block unresolved writes. No live login/upload tests without an approved account and exact content.
- Markdown raw HTML stays disabled, previews must not fetch external images, and local image paths must remain within the article directory. Plan/validate never write files or read credentials.
- Confirm each platform's supported interface before implementing an adapter; document unsupported capabilities explicitly.
- Credentials and browser sessions belong in user-controlled secure storage, never repository files or logs.
- Publishing an article, releasing a package, and pushing code are separate actions requiring explicit user authorization.
